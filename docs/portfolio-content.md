# 作品案例内容与证据清单

本文档是仓库维护者使用的作品内容校验表，不是线上页面文案。“待确认”、采集问题和占位符不得直接渲染到对外页面。

## 证据规则

每一条成果陈述都应属于以下三类之一：

1. **已验证结果**：有可核对的测试记录、上线数据、官方获奖页、证书、展览信息或真实产品链接。
2. **设计产出**：已完成的研究框架、信息架构、原型、视觉系统、影像或实体作品，但没有真实使用成效数据。
3. **预期价值**：尚未在真实环境验证的效果假设。必须使用“旨在”、“尝试”、“预期”等准确措辞，不能写成已发生的结果。

不得猜测或补齐研究人数、测试轮次、效率提升、用户满意度、合作机构、客户关系和技术上线状态。页面有陈述但尚未附证据时，将其作为待核对事项，不将陈述本身当作证据。

## 每个案例应收集的字段

| 字段 | 需要记录的内容 | 可接受的证据 |
| --- | --- | --- |
| 项目性质 | 个人/课程/团队/竞赛/客户/展览，是否为概念项目 | 任务书、官方页、课程记录或书面说明 |
| 时间 | 开始/结束时间、总周期、阶段节点 | 文件时间线、评审或提交记录 |
| 团队 | 团队规模、成员职能、指导者/合作方 | 成员名单、分工记录；公开姓名需征得同意 |
| 本人职责 | 本人主导、共同完成和未参与的部分 | 可与项目文件和团队分工互相印证 |
| 研究 | 方法、样本量、招募条件、时间、问题与关键发现 | 匿名化笔记、问卷、访谈提纲、数据来源 |
| 方案决策 | 考虑过的替代方案、取舍和改版原因 | 草图、版本对比、评审记录 |
| 原型/产出 | 产品边界、实现程度、技术与可访问状态 | 原型、代码、视频、展板、实物照片 |
| 测试 | 测试对象、任务、轮次、观察指标和改动 | 测试脚本、记录、前后版对比 |
| 结果 | 已验证结果、设计产出或预期价值 | 数据、官方结果、上线记录、用户反馈 |
| 限制 | 样本偏差、尚未验证之处、技术/合规风险 | 团队复盘或后续研究计划 |
| 授权与来源 | 品牌素材、用户数据、照片、字体和音频的使用权 | 授权文件、来源链接、许可证 |

## 首页案例的最小信息块

每个精选案例应先用 20–30 秒可读的摘要告诉读者：

- 这是什么类型的项目，解决什么问题。
- 时间、周期、团队规模和本人角色。
- 本人做了哪些关键决策。
- 最终产出及其当前状态。
- 一条最有说服力的可核对结果；若没有，明确写“概念原型/设计产出”。

详情页建议使用：摘要 → 背景与约束 → 研究证据 → 关键洞察 → 方案取舍 → 原型 → 测试与迭代 → 结果与限制。

## 01 ICU+

**页面已有**：2026；ICU 家属沟通与医护协同高保真概念方案；家属端、医护数字孪生工作台、Pocket Lens 硬件与演示视频。Outcome 已明确区分“设计产出”与“预期价值”，且注明尚未经过真实医疗场景验证。

**待补证据**：

- 项目是课程、个人概念、团队项目还是机构合作；周期、团队与本人占比。
- 家属和医护 Persona 的研究来源；是否访谈真实医护/家属，样本和招募条件是什么。
- 病情摘要、AI 咨询、高危沟通留痕与数字孪生的可行性、信息安全和医疗合规边界。
- 是否有医疗专业人员评审、可用性测试、高压情景测试和迭代记录。
- “信息更透明、家属更安心、沟通更可复用”是实测结果还是设计目标。

**当前定位**：“医疗服务设计概念 / 高保真原型”，Outcome 已改为“设计产出与预期价值”。

## 02 万物链 Bio Campus

**页面已有**：2025；校园生态数字导览概念原型；Web、移动端、App 动效和系统闭环规划展示。页面已明确内容采集、专业审核与社区参与尚待真实运营验证。

**待补证据**：

- 项目性质、周期、团队规模，以及信息架构、品牌、UI 和线上页面各自的本人贡献。
- 校园物种、栖息地和生态信息的来源、更新责任与专业审核方式。
- 是否进行校园观察、学生/访客访谈、任务流程测试，以及样本和改版证据。
- “可持续积累的数字生态平台”是已运营能力还是概念闭环；当前是否有可访问线上版本。
- “商业闭环”中各参与方、激励来源和可持续性假设是否已被验证。

**证据补齐前的建议定位**：“校园生态平台概念与交互原型”。

## 03 GAFA 路标改良系统

**页面已有**：2025；广美校园导览、实体标识改良、移动端与两个可访问的线上导览入口。

**现有可核对入口**：

- `https://gagafa.netlify.app/gafa1.0/`
- `https://gagafa.netlify.app/gafa2.0/louceng`

**待补证据**：

- 项目性质、周期、团队与本人分工。
- “信息层级混乱、地标弱、方向感缺失、指引不连续”的现场调研方法、点位和样本。
- 对新生、校内学生和访客的找路任务测试；有无改良前后的到达时间、错误转弯或求助次数对比。
- 线上页面是原型还是持续运营产品；实体标识是提案、局部测试还是已落地。
- 校名、校徽、地图和建筑信息的公开展示授权。

**证据补齐前的建议定位**：“校园导视提案 + 可访问 Web 原型”；除非确有落地证明，不使用“已重构校园导览体验”的结果式表述。

## 04 情绪地图 Emotional Map

**页面已有**：2026；面向白领与商务人群的情绪状态响应式工作服务概念；用户研究、情景、信息减负对比、响应模式和最终界面。

**待补证据**：

- 项目性质、周期、团队和本人分工。
- “通过用户研究”的具体方法、样本量、受访者条件、分析方式与原始证据。
- 系统如何得知情绪/能量状态：用户主动选择、行为推断还是生理数据；如何同意、更正和退出。
- 信息减负是否做过理解率、任务完成、决策负担或主观压力测试。
- 与 Emotional Lens 的研究边界、核心机制和产出差异；是同一课题的两次迭代还是独立项目。

**证据补齐前的建议定位**：“情绪响应式工作服务概念原型”。如无足够独立证据，考虑与 Emotional Lens 合并为一个完整案例。

## 05 Emotional Lens

**页面已有**：2026；未来情绪感知服务概念；Emotional Lens、Emotional Agreement 和可访问的线上概念网页。

**现有可核对入口**：`https://imaginative-kheer-c2fc30.netlify.app/`

**待补证据**：

- 项目性质、周期、团队与本人分工。
- “从可用性、用户旅程、个性化到情绪感知”的趋势判断需要可引用的研究/行业来源和时间范围。
- Emotional Agreement 中同意、可撤回、数据最小化和误判处置的具体流程。
- 网页是叙事原型还是可操作产品原型；有无概念理解或交互测试。
- 与“情绪地图”的关系和非重复贡献。

**证据补齐前的建议定位**：“思辨性服务设计 + 可访问概念网页”，不暗示系统已具备真实情绪识别能力。

## 06 Music and Economics

**页面已有**：2026；围绕宏观经济、情绪与音乐文化的大型数据可视化展板。

**待补证据**：

- 项目性质、周期、团队与本人分工。
- 每张图表的数据集、来源链接、采集年份、地域、指标定义、清洗方式和许可证。
- 音乐类型、情绪、消费和经济周期的分类方法，以及是否存在主观编码。
- 如果展板只展示共变关系，需加入“相关不代表因果”和样本限制。
- 是否进行图表理解度、读取顺序或信息负荷测试，以及根据测试修改了什么。

**证据补齐前的建议定位**：“数据可视化与信息图研习”，不把视觉关联写成宏观经济研究结论。

## 07 数字餐桌 The Table

**页面已有**：2026；共餐、数字侵入与真实疏离议题的 3D 批判性数字艺术；项目展板、交互框架、论坛现场记录和证书图片。对外页面不再宣称无法核验的首尔国立大学邀请关系。

**待补证据**：

- 项目性质、周期、团队、本人在叙事、3D、交互与展览呈现中的准确分工。
- 展览/论坛的官方中英文名称、主办方、日期、城市、项目入选方式和官方入口。
- “受邀参与首尔国立大学相关论坛与展览”必须与证书/官方信息逐字核对，避免把“相关”扩大为直接主办或学术认证。
- 作品的实际交互方式、技术工具、现场设备和观众体验路径。
- 如果有现场观察或评论，记录数量与来源；如无，不把展出经历等同于用户效果。

**证据补齐前的建议定位**：若证书能够印证，使用“公开展出的互动数字艺术作品”；否则使用“批判性数字艺术概念”。

## 08 喜茶阿喜全身像

**页面已有**：2024；品牌角色全身形象设计；当前仅标注为“比赛投稿作品”，不对外宣称未核验的获奖名次。

**待补证据**：

- 活动的官方全称、主办方、组别、年份、评选方式和官方结果页/证书。
- 是个人还是团队参赛，本人完成的角色设定、草图、定稿和应用延展范围。
- 品牌素材、商标和获奖作品的作品集展示权。
- 该项目是公开征集/竞赛作品还是喜茶委托的商业项目。没有委托合同时不得暗示客户合作。
- 页面所述 IP 表情、包装、活动视觉和衍生品是已完成应用还是未来可延展方向。

**证据补齐前的建议定位**：“品牌角色设计竞赛作品”。获奖名次只在官方材料核对后保留。

## 09 其他能力 Additional Making Skills

**页面已有**：2024–2026；场景建模、战报设计、手工书与手绘四类练习。

**待补证据**：

- 每件作品的名称、年份、背景、个人/团队性质、本人分工和使用工具/材料。
- 战报的委托方、数据与图像来源，以及是否允许公开。
- 3D 场景是独立建模、基于教程练习还是使用现成资产；需按许可证标注第三方资产。
- 手工书与手绘的主题、尺寸、媒材、制作过程和完成周期。
- 当前的问题陈述是编辑备注（“作品集还需要如何证明……”），不应作为公开案例问题。

**建议定位**：这不是一个项目，建议改为“制作与视觉基础档案”，每件作品使用简短事实标签，不套用 Problem / Contribution / Outcome 案例模板。

## 内容优先级

### 第一批：首页精选案例

如目标是交互/产品/服务设计岗位，先为 GAFA、ICU+ 和万物链补齐最小信息块。GAFA 已有可访问网页，应优先核对其真实落地边界；ICU+ 和万物链则需优先确定项目性质、研究样本和验证状态。

### 第二批：外部认可

核对数字餐桌的展览/论坛材料与喜茶的竞赛结果。官方名称、日期、主办方、名次和链接一旦核对，可用作首页信任证据。

### 第三批：去重与方法论

明确情绪地图与 Emotional Lens 的关系，必要时合并。为 Music and Economics 建立数据来源附录。将“其他能力”从案例叙事改为媒介能力档案。

## 发布前编辑检查

- [ ] 所有项目都标明性质、时间、团队和本人角色。
- [ ] 所有研究陈述都有方法和样本说明。
- [ ] 所有成果都被标记为已验证结果、设计产出或预期价值。
- [ ] 获奖、展览、合作和上线陈述均与官方材料核对。
- [ ] 团队成员、受访者、照片与品牌素材已取得展示授权。
- [ ] 用户材料已匿名化，没有展示敏感医疗、工作或个人数据。
- [ ] 对外链接仍可访问，并且能清楚表明实现状态。
- [ ] 页面内没有 TODO、编辑提问、未解释的占位符或对证据的夸大描述。
